## Contract with F2 (as built)

- Route paths: `/login`, `/`, `/sast`, `/dast`, `/history`, `/scans/$scanId`, `/reports/$reportId`, `/settings/...`. F2's pages read `scanId` and `reportId` with
  `useParams({ strict: false })`, which matches what F2 wrote. `router.tsx` imports `SastPage`, `DastPage`, `ScanDetailPage`, `ReportPage` from F2's files (all four exist).
- `apiFetch` accepts `query` values of `string | number | boolean | undefined` and also `string[]` (repeats the key); `ApiError.problem` also has optional `code` and `errors`.
- `useMeQuery()` (api/me.ts) returns `Me | null`; `Me` = `{ id, name, email, role, defectdojoUrl, lastLogin }` (a superset of the agreed shape). `useMe()` from `lib/auth`
  returns `{ user, isLoading, error, refetch }`. The `Me` and `Role` types are re-exported from `lib/auth.tsx`.
- `SeverityBadge({ severity, count? })`, `StatusBadge({ status, label? })` (knows scan, job, import, report and verdict states; unknown states are neutral),
  `SeverityCountBadges({ counts })`.
- `api/reports.ts` exports everything F2's report page and scan detail import (`reportCsvUrl`, `reportHtmlUrl`, `reportPdfUrl`, `useCreateReport`, `useReport`, `useReports`,
  `useReviewReport`, `Report`). `useReport` polls every 3 s while `status` is `pending`.
- The router uses its own search codec (`?tool=a&tool=b`, values stay strings) instead of TanStack's JSON-in-the-URL default. F2 pages that read search params get
  strings or string arrays.

## Deviations from the plan or the task text

1. **No generated client.** `src/api/schema.d.ts` cannot be produced here; the API modules are hand-written. `npm run gen:api` and `openapi-fetch` stay in
   `package.json` for later; plan task "hooks in `src/api/hooks/`" is `src/api/*.ts` as the task text says. Where the backend differs from the plan, the backend won.
2. **`Select` is a styled native `<select>`**, not Radix Select: labelled by `<Label htmlFor>`, works with the keyboard and screen readers in every browser and in tests.
3. **Settings pages for which no endpoint exists yet are not built:** scanner health, content versions, image-update approvals (M8) and vendor assessments (M10).
   The sub-navigation list is one array (`SETTINGS_PAGES` in `routes/settings/layout.tsx`) plus one route line in `router.tsx` per page.
4. **Schedules page creates `weekly` and `poll` schedules only**; DAST schedules are listed, switched on or off and deleted, but creating one needs the target picker
   (M9). Blackout windows are shown as a count; they are not editable in the UI.
5. **Historical data:** page-by-page navigation (Previous and Next with cursors held in component state), not infinite scroll; "started by" is a user-ID text box because there is no
   users list endpoint; "tools" is a comma-separated text box (tool names come from the catalogue and grow in M8); the application and vendor drop-downs load the first
   200 by name. A scan row links to scan detail only (the report link is on that page): there is no scan -> report lookup in the history response.
   "Export CSV" is shown on the Findings tab only (the endpoint exports findings with the findings filters).
6. **`GET /me/defectdojo-account` is read once per page load** (`staleTime`/`gcTime` infinite, no refetch): the backend returns the initial password only on the first call.
   After a reload the person sees the reset button instead. Opening Home therefore "uses up" the one-time password even if nobody looked at it; this is the backend behaviour.
7. **Template preview** is a `POST` (needs the CSRF header), so the HTML is fetched through `apiFetch` and shown in `<iframe sandbox="" srcDoc=...>` instead of `src=`.
8. **`tsconfig.json` types** now include `node` (Playwright specs use `Buffer`), and `@types/node` is a dev dependency.
9. **`App.test.tsx` was rewritten** (it tested the M0 placeholder `App`).

## Backend facts worth knowing (mismatches with the plan text)

- `GET /me` returns `defectdojo_url` without `/login`; the button appends `/login`. `GET /summary` returns the same `defectdojo_url`.
- `POST /integrations/github/test` waits up to 45 s for the worker before answering `202` with status `running`; the Settings page then reads `GET /integrations/github`
  every 3 s until `last_test_at` is set. Gateway proxy timeouts must be above 45 s for `/api/` (nginx default `proxy_read_timeout` is 60 s).
- `GET /history/scans` has no `cwe`, `severity` or `source` filters; the UI only sends scan-relevant filters on the Scans tab.
- `GET /templates/{id}/download` has no file for the built-in template; the table offers "Download default template" (`/templates/default/download`) for it.
- The audit viewer's `actor` filter matches the actor label (name or e-mail), not the user ID.
- `PATCH /applications/{id}` (Analyst or Admin) is what confirms a repository and switches automatic scans on; the Repositories page calls it directly.

## How to verify on Ubuntu (nothing here has been run)

1. `cd frontend && npm install` (creates `package-lock.json`; none exists yet) then `npm run typecheck`, `npm run lint`, `npm test`. Expect a few first-run fixes:
   - TanStack Router typing without a registered router (`Link to=...`, `Navigate search=...`, `useSearch({ strict: false })`) is the most likely place for type errors;
     I deliberately did not call `declare module "@tanstack/react-router" { interface Register ... }` so route strings stay plain strings.
   - `@typescript-eslint/recommendedTypeChecked` may flag a few `as` casts or promise handlers I could not check.
   - `tailwind-merge` v3 and Tailwind v4 custom colour names (`bg-sev-critical-bg`): `SeverityBadge.test.tsx` asserts the class names survive `twMerge`.
2. `npm run build`, then `python scripts/dev.py up --profile dev` and open `https://securescan.localtest.me:8443/`.
3. `npx playwright install chromium` then `npm run e2e` (needs the dev stack with the mock OIDC provider). `signInAs` assumes the mock login form has `input[name=username]`,
   `textarea[name=claims]` and a submit input (verify on the first run; see build note M2 item 2). `history.spec.ts` skips the row-link test when the history is empty.
   `settings.spec.ts` creates a verdict policy for data classification `public` and switches it off again so it can be re-run.
4. By hand: sign in as Analyst (Settings link absent, `/settings/templates` goes Home), as Admin (every Settings page loads), Home: DefectDojo panel, Historical data:
   change filters, reload, Export CSV opens a download whose first line is the header.
