## How the schema was produced

The models and `0001_initial_schema.py` were emitted from **one column specification** by a throw-away generator script (not committed),
then reviewed. This guarantees they agree (a hand-written pair could not be checked without Python 3.14 and SQLAlchemy here).
The migration is plain `op.create_table` / `op.create_index` calls with explicit constraint names (no autogenerate, no helper
indirection); the generated files are the source of truth from now on and are edited by hand.

## Deviations from the plan or the task text

1. **Enqueue is not in the same transaction as the ORM write.** Procrastinate defers through its own pool; it cannot join a
   SQLAlchemy transaction through its public API. Pattern documented in the conventions (7.2): commit the state row, then
   `defer(...)`, with the `stalled_jobs` hook (M3) re-deferring orphaned `queued` rows; `queueing_lock` makes that idempotent.
2. **Mock OIDC roles come from the login form, not from the user name.** mock-oauth2-server builds the token callback from the
   interactive login form (user name = `sub`, optional "Claims" JSON), so `deploy/dev/mock-oidc.json` only enables interactive login;
   you type `{"roles": ["Admin"]}` or `{"roles": ["Analyst"]}` in the claims box. Verify on first use; the fallback is Keycloak (plan 2.2).
3. **Dev issuer name**: `http://mock-oidc.localtest.me:8082/default` (browser resolves `localtest.me` to 127.0.0.1; the api container
   maps the same name to `host-gateway`) so the issuer in the token is identical for both sides.
4. **`DELETE` archives** applications, versions, targets and vendors (`archived_at`) instead of removing rows: history is permanent.
   `PATCH {"archived": false}` (Admin) restores. Duplicate names remain reserved while archived.
5. **Extra table `uploads`** (state of a chunked upload) and extra periodic task `session_cleanup` (expired sessions, stale uploads).
   Extra endpoint `POST /uploads/{id}/complete` (finalise) and `GET /uploads/{id}` (resume offset).
6. **Periodic tasks are registered once in `maintenance.py`** and call `run_periodic(name)`; later milestones register the real code
   with `@periodic_hook(name)` (no edits to `maintenance.py`, no duplicate task names). `credential_expiry_alerts` is real in M2:
   gauge `securescan_credentials_expiring` plus one `credential.expiring` audit event per credential (the "admin notice").
7. **PyJWT verifies the ID token**, Authlib does the authorization URL and code exchange (Authlib's `authlib.jose` is deprecated in 1.6+).
8. **CSRF token is stored on the session row** (double submit: cookie = header = session value) instead of an HMAC.
9. **Audit safety net**: `RequestMiddleware` writes a generic `http.<method>` event when a signed-in user's successful write
   request recorded no audit event, in addition to the explicit events. Request id header `X-Request-ID` and API latency metrics are in the same class.
10. **No ORM relationships**; ids and joins only. `Artifact.scan_id/job_id`, `Application.last_scan_id`, `RepositoryHead.last_scan_id`
    are soft references (no FK) to avoid circular table creation.
11. **Settings added** beyond plan 7.1 (all with defaults; see conventions section 2), including `master_key_previous`, `cookie_secure`,
    `session_*`, `upload_*`, `worker_metrics_*`, `network_*`, `content_root`, DefectDojo and SonarQube account names and passwords.
12. **Gateway DefectDojo block is live** (not a 503 stub): it returns a 503 text only while `http://nginx:8080` is unreachable.
13. Python 3.9 compatibility: `Enum` classes are `(str, enum.Enum)` (not `StrEnum`; `# noqa: UP042`), `uuid.uuid7` is used when
    present with an RFC 9562 fallback in `util.new_id`.

## Not verified, and how to verify on Ubuntu 24

Run first, from `backend/`: `uv lock && uv sync && uv run ruff format . && uv run ruff check . --fix && uv run mypy securescan && uv run pytest tests/unit`.
- **Lint and types**: expect work. Ruff E501 (100 columns) will flag some long strings and comments that `ruff format` cannot wrap; import
  order (I001) is auto-fixable; mypy strict will report missing generics and `Any` leaks, mostly in `api/*` and `auth/oidc.py`.
- **Unit tests** were written but never run. The most likely first failures: Procrastinate attribute names (`app.tasks`, `open_async`),
  SQLAlchemy `ColumnElement` import path, `jwt.PyJWK`/`RSAAlgorithm.to_jwk(..., as_dict=True)` in `test_oidc.py`, and the `starlette`
  cookie header casing in `test_csrf_and_sessions.py::test_session_cookie_attributes`.
- **Migrations**: `python scripts/dev.py up` then `python scripts/dev.py migrate`; then from `backend/` with `SECURESCAN_DATABASE_URL` and
  `SECURESCAN_DATABASE_PASSWORD` set (port-forward `db`) `alembic check` must report no drift (compare_type is on; Procrastinate objects are
  excluded in `env.py`). The Procrastinate `schema.sql` is executed on the raw DBAPI cursor; `resources.files("procrastinate").joinpath("sql", "schema.sql")`
  assumes that path in procrastinate 3.x. `docker exec securescan-db-1 psql -U postgres -d securescan -c '\dt'` should list 23 tables plus `procrastinate_*`.
- **Worker**: `docker logs securescan-worker-1` shows `tasks_loaded` and `worker_started` with all 14 periodic task names; `curl worker:9100/metrics`
  from another container works. Unverified: `@app.periodic` + `queueing_lock` on every periodic task (if Procrastinate rejects a `queueing_lock` on periodic
  tasks, delete the `queueing_lock=` arguments in `jobs/maintenance.py`), `app.run_worker_async(queues=, concurrency=, name=)` signature, `PsycopgConnector(conninfo=...)`.
- **Sign-in**: with `--profile dev`, `GET https://securescan.localtest.me:8443/api/v1/auth/login` redirects to the mock; sign in with claims
  `{"roles":["Analyst"]}`; `GET /api/v1/me` shows the role; no roles gives the 403 problem. Check the cookie reaches `dojo.securescan.localtest.me`
  (Domain attribute). Authlib's `AsyncOAuth2Client` calls (`create_authorization_url`, `fetch_token` kwargs) are the least certain part.
- **Gateway**: `docker exec securescan-gateway-1 nginx -t`; the `map` with named captures (`$portal_host`, `$dojo_cookie`) and `proxy_method GET`
  in the auth subrequest are unverified. Without a session `https://dojo.securescan.localtest.me:8443/` must redirect to the portal `/login`.
- **Audit trigger**: `UPDATE audit_events SET action='x'` must fail with "audit_events is append-only".
- **Chunked upload**: 100 MB upload with `curl -X PATCH --data-binary @chunk -H 'Content-Range: bytes ...'` and compare SHA-256.
- **Integration tests**: `SECURESCAN_INTEGRATION=1` plus a reachable database (see the docstring of `tests/integration/conftest.py`).
