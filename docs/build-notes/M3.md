# M3 build notes: scan runner, workspaces, Semgrep and Gitleaks

Written on a machine with no Docker, uv, Python 3.14 or installed dependencies, so **nothing in this milestone was run as written**.
Checks that were possible: `python scripts/check_imports.py` (byte-compile on Python 3.9, import and name cross-check: 0 problems after the
last edit), `yaml.safe_load` of every YAML file, and a throw-away harness (not committed) that ran the stdlib-only logic of
`runner/sources/zip.py`, `runner/validate.py`, `runner/launcher.py` (request body, path mapping, run/timeout/cancel/error mapping against a
fake Docker API), `runner/sources/github.py` (command construction, clone sequence with a faked git runner, real `git` for branch keeping and
ref resolution) and `runner/events.py` with the third-party imports stubbed, on Windows. Everything else (catalogue models, scan creation,
executor, recovery, API, SSE, seeding, Procrastinate integration) is reviewed by reading only. The unit tests were written for Ubuntu and
were not run under pytest.

## How it fits together (for the milestones that follow)

- **Calling convention other milestones already use**: `create_scan(session, version_id=, profile_name=, trigger=, requested_by=, target_ids=[one],
  options={"commit": sha, "trigger_detail": "..."}, idempotency_key=)` returns the `Scan` (M7 poller and M9 schedules call exactly this).
  It writes the rows in the caller's transaction and registers a SQLAlchemy `after_commit` hook on the session; after the *outermost* commit
  it defers one `scan_job` per job (`queueing_lock` per application, version, target, tool, source reference; `lock` `tool:<name>:<job id mod max_parallel>`,
  or the entry's fixed `lock`). A full 40-hex commit in `options["commit"]` pins the commit; a branch or tag name becomes `Scan.source_ref`;
  the first job to clone claims `Scan.commit_sha` and the others check out that commit.
- **Adding a tool (M8/M9)**: a catalogue entry (`scanners/catalogue.yaml` or `catalogue.d/*.yaml`), a module `runner/tools/<tool>.py` with `BUILDER`,
  a profile (new version of `code-standard` or a new file in `scanners/profiles/`), one `SECURESCAN_IMAGE_<LOCK>: ${IMG_<LOCK>:?...}` line in the worker
  service of `deploy/compose.yaml`. `DefaultToolBuilder` builds the container from the entry; override `prepare`, `optional_args`, `content_path`, `extra_env`,
  `post_run`, `build_command` as needed. Mounts other than `out` must be read-only (catalogue validation).
- **Sources**: `register_source_handler("image", handler)` (M8) and `register_source_handler("url", handler)` (M9: a handler that fills nothing and returns
  `SourceInfo(kind="url", is_git=False)`). Until then those kinds end the job `failed` with a plain reason.
- **Hand-over to M4**: after the job's final state is committed, `jobs.import_job.enqueue_import(session, job_id)` is called for every final job (it settles
  failed, cancelled and timed-out jobs itself). A tool skipped as not applicable ends `completed` with `outcome_reason` "Skipped: ..." and is settled through
  `settle_without_import` (`mark_import_skipped` + `finalize_scan_if_ready`). API cancel of still-queued jobs calls `settle_cancelled_jobs` after its commit.
  `Scan.state` is the roll-up of the job states (`finalize_scan`); the verdict stays M4's.
- **Log streaming (recorded choice)**: every log line is scrubbed, appended to `<artifacts>/scans/<scan>/<job>/job.log` and published with `pg_notify` on channel
  `scan_<scan id>` in batches under 7 KB. The SSE endpoint sends a snapshot, the tail of each job log (from the file; it needs the artifacts volume), then `LISTEN`s and
  re-reads the database every 5 s, so a missed NOTIFY only delays an update. The final log is also stored as an `Artifact` of kind `log`.

## Deviations from the plan or the task text

1. **`out` directory is mode 0777** (other workspace directories 0775). With all capabilities dropped even a root container has no permission override, and
   scanner images run under their own uid; a directory only the worker's uid can write would break them. Files in `src` and `config` are world-readable.
2. **Entry `entrypoint: [""]`** in the catalogue clears the image entrypoint so that `command` is the whole argv, exactly as in the plan text
   (`semgrep scan ...`, `gitleaks git ...`). S7 confirms; if an image refuses an empty entrypoint set `entrypoint: null` and drop the leading binary name.
3. **Gitleaks runs as `1000:1000`**, not root (the plan leaves it to S7). `GIT_CONFIG_*` sets `safe.directory=/src` for both tools. If S7 shows a problem, change `user:`
   in the catalogue only.
4. **`.semgrepignore` is removed** from the scanned source like `.gitleaksignore` (plan names only the latter), so that the owner of the code cannot hide files; both removals
   are recorded as "applied exclusions" and in `coverage_note`. Gitleaks and Semgrep also remove the files one directory level down (zip with a wrapper folder).
5. **Exit code 1 of Semgrep maps to `completed`** (the plan says 0 completed, >=2 failed). The command has no `--error`, so 1 should not occur.
6. **Limits live in `limits` + top-level `timeout_minutes`** of the catalogue entry; a profile job may override timeout and limits within fixed ceilings
   (16 CPUs, 32 GB, 12 h). A scan request can only add tool options (for example `exclude`), never limits.
7. **Profile files**: `scanners/profiles/semgrep.yaml` has `tool:` instead of `profile:` (it is the plan's Semgrep exclusion list, not a scan profile) and is never seeded.
8. **Same-input repeats collapse before the queue**: a second identical request while the first scan is still `queued` returns the first scan (`X-Scan-Collapsed: true`)
   instead of creating a scan whose jobs the `queueing_lock` would refuse. The `queueing_lock` remains as the safety net (a job refused by it is cancelled with a reason).
9. **Enqueue is after the commit, not in the transaction** (M2 deviation 1). `stalled_jobs` re-defers anything lost, after `job_queued_grace_seconds` (180 s).
10. **Container names are `securescan-job-<job id>`** and recovery finds containers by that name (`inspect`) instead of by label listing; `list_by_label` exists and the proxy allows it.
11. **No network access from the executor for GitHub tokens**: the GitHub clone uses M7's `integrations.github.connection` (`get_connection`, `github_client`, `github_hosts`)
    and `runner.egress.egress_lease`; there is no second token minter in this milestone.
12. **Idempotency keys** are limited to 91 characters (stored as `<user id>:<key>` in a 128-character column).

## Not verified, and how to verify on Ubuntu 24

Run first, from `backend/`: `uv run ruff format . && uv run ruff check . --fix && uv run mypy securescan && uv run pytest tests/unit`.
- **Lint**: expect E501 on long docstrings and comments (this milestone follows the M2 style); the formatter cannot wrap them. Consider `ignore = ["E501"]` in `pyproject.toml`.
  Expect mypy findings on `Any` use in `api/scans.py`, `executor.py`, `launcher.py` (the docker SDK is untyped).
- **Pydantic details**: validators named `_x` with `@field_validator` + `@classmethod`; `model_validator(mode="after")` as instance methods; `exit_codes` keys must stay quoted strings in YAML.
- **Procrastinate**: `@app.task(pass_context=True, retry=RetryStrategy(..., retry_exceptions={LauncherError}))` and `context.job.attempts`/`context.job.id`;
  `task.retry_strategy` (used in `test_scan_job_task_and_hooks_are_registered`); raw SQL on `procrastinate_jobs` (`status::text`, `args ->> 'job_id'`, `UPDATE ... SET status = 'failed'`)
  in `domain/scans.py` and `runner/recovery.py`. If the table or enum changes in a newer release the stalled-job sweep fails (it logs and continues).
- **psycopg**: `AsyncConnection.notifies(timeout=...)` ends the iteration after the timeout (psycopg 3.2+) in `api/scans.py::event_stream`.
- **SQLAlchemy**: `after_commit` listener on `AsyncSession.sync_session` creating a task with `asyncio.get_running_loop()` (`domain/scans.py::_after_commit`); `update(...).returning`
  in `executor.py::_claim_commit`.
- **Docker SDK**: `APIClient(version="1.44")`, `create_container_from_config(body, name)`, `wait(cid, timeout)` raising `ReadTimeout`, `logs(stream=True, follow=True)`, `inspect_volume`,
  `containers(all=True, filters=...)`. Check with `docker ps` during a scan, `docker inspect <container>`: no network, read-only rootfs, caps dropped, uid from the catalogue, label `securescan.job_id`.
- **Socket proxy** (`deploy/socket-proxy/args.env`): the regexes are derived from the SDK request shapes, **not confirmed**. Spike S2 (`sh spikes/s2/run.sh all`) must confirm that the proxy matches the path
  without the query string, that `SP_ALLOWFROM=worker` works, the numbered variable names, the comma-separated `SP_ALLOWBINDMOUNTFROM`, and whether the proxy needs `user: 65534:<docker gid>`.
  Without `user:` the scratch image runs as root, which can read the socket. Replace the file with S2's output if it differs.
- **Image entrypoint** `[""]`, **Semgrep default skips** (`tests/`, `vendor/`, `node_modules/`, `build/`, `dist/`, `*.min.js`, files over 1 MB are the plan's list, recorded as built-in exclusions),
  **HOME=/tmp and tmpfs** (S7 `docker diff` shows the paths Semgrep and Gitleaks really write), **Gitleaks writes an empty `[]` report** when nothing is found (else the job ends `failed`: "report was not produced").
- **Symlink chain check** in the zip unpacker relies on `os.path.realpath` resolving `link/..` component by component (Linux). It could not be run here.
- **Compose**: `${IMG_SEMGREP:?...}` needs `dev.py pin-images` first (as `IMG_PYTHON` already does). `../scanners` is relative to the project directory `deploy/`.
- **Acceptance** (plan M3): run `SECURESCAN_INTEGRATION=1 python scripts/dev.py test integration -k semgrep_gitleaks` with the stack up, the images pulled, and rules in `content/semgrep/rules` (S7's `prefetch.sh semgrep`
  writes `semgrep-rules`; the builder accepts `content/semgrep/rules` or `content/semgrep-rules`). Manual checks: GitHub scan at a commit (`.git/config` has no remote: `docker run --rm -v ... ` is not needed, the worker keeps
  nothing after the job; verify during the clone with `docker exec securescan-worker-1 cat /var/lib/securescan/workspaces/<job>/src/.git/config`), kill the worker mid-scan and watch the job go back to `queued`
  (start-up hook) or be failed after the second attempt, three queued scans of a tool with `max_parallel: 1` (set it temporarily) never run together.
