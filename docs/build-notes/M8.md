# M8 build notes: remaining code scanners, SonarQube on demand, updaters

Written on a machine with no Docker, uv, Python 3.14 or installed dependencies, so **nothing in this milestone was run under pytest or
against Docker**. What was executed (Python 3.9, standard library plus PyYAML only, with every other import stubbed in a throw-away
harness that is not committed): the image extraction (whiteouts, opaque directories, symbolic links rewritten into the root, hard
links, traversal, size and entry limits, OCI layouts, compressed layers), the Java artifact discovery and class-name parser, the SpotBugs
command assembly, the licence filter, the lock-file parser, symlink switching (not on Windows, which refuses to replace a link), pruning,
the Grype status parser, the expectation matcher, and the update flows of Semgrep rules (first install, same commit, gate rejection,
licence-only AGPL clone, clone failure), Grype and Nuclei with a fake container runner. The shipped catalogue was checked with a mirror of
the Pydantic rules (`mini_catalogue_check`: 0 problems). `python scripts/check_imports.py`: 0 problems. Every other line, in particular all
Pydantic models, FastAPI endpoints, SQLAlchemy statements, the Docker interaction and every test under `backend/tests/`, is reviewed by
reading only.

  but belong to the same work: `skopeo.yaml` (image intake) and `nuclei-templates.yaml` (`nuclei-templates-update`, `nuclei-templates-validate`;
  M9's scan entry `nuclei` is separate). `max_parallel`: sonarqube 1, spotbugs 1, dependency-check 1, semgrep 2 (M3), syft-grype 2.

Runner (`backend/securescan/runner/`)
- `tools/syft_grype.py`: job `syft-grype`. `prepare` requires an active `grype_db` content version, runs the Syft container itself (entry `syft`) and
  validates the SBOMs; the executor then runs Grype (entry `syft-grype`) with the database from `<content>/grype-db`. `post_run` stores both SBOMs
  as `ArtifactKind.SBOM`. `classify_exit` reads the job-log tail and, when Grype refused a stale or missing database, ends the job with a plain reason
  ("older than the allowed 5 days ..."). Env `GRYPE_DB_MAX_ALLOWED_BUILT_AGE` comes from `SECURESCAN_GRYPE_DB_MAX_AGE` (default 120h).
- `tools/dependency_check.py`: command per plan (`--noupdate`, flags off, `--propertyfile /config/odc.properties`), `--disableCentral` and no network in
  the no-disclosure mode (default on for vendor applications, `options.no_disclosure` overrides), `--proxyserver/--proxyport` through the egress
  proxy otherwise; blocked until the first NVD update succeeded; waits while an update rewrites the data; exit 14 -> `completed_partial`.

- `tools/spotbugs.py`: Java artifact discovery (`discover_java`: JAR/WAR/EAR outside library directories, package roots of class trees found by reading

- `tools/sonarqube.py`: language detection and skip rules (C# only, image without application source), `ensure_running`, project creation, a per-job
  `PROJECT_ANALYSIS_TOKEN` (expires after one day, the only credential of the scanner container, revoked after use), `sonar.java.binaries` from the
  discovery or the empty-directory fallback, post-run CE polling, quality gate, measures, issues export; quality gate and measures are written into

- `tools/_support.py` (new, underscore name so the registry skips it): `spec_from_entry` (container spec from a catalogue entry for containers that are not

- `sources/image.py`: `parse_image_reference` (strict, never shell-interpreted), skopeo run through the shared egress proxy with the registry's own hosts

## Deviations from the plan or the task text

1. **Grype database and NVD data live in the content volume** (`<content>/grype-db`, `<content>/odc-data`, mode 0777 created by the worker), not in the
   Compose volumes `grype_db` and `odc_data`. Reason: a fresh named volume is root-owned and the containers run as uid 1000 with all capabilities dropped; a
   directory the worker (uid 1000) creates works for every uid, and the worker can read it (sizes, existence). The two Compose volumes stay unused.
2. **Image intake uses the shared egress proxy of M7** (`egress_lease`), not a per-job squid, and the skopeo, updater and Dependency-Check containers join
   the egress client network (`SECURESCAN_EGRESS_CLIENT_NETWORK`, default `securescan_backend`). The M7 proxy lives on `backend` + `egress`, so
   these containers can in principle reach the other backend services and bypass the proxy; they carry no secret except the single job credential.
   See open issue 1.
3. **The image archive lives in `config/image.tar`, not `src/image.tar`**, so Gitleaks, Semgrep and Dependency-Check do not scan the compressed layers a
   second time. Syft reads `docker-archive:/config/image.tar`.
4. **Skips happen inside `prepare`** through `securescan.runner.tools._support.skip_job`, which raises the executor's private `_Finish(COMPLETED, reason,
   skipped=True)`. Reason: the executor calls `applicable()` before the source exists, but SpotBugs and SonarQube must look at the source. Ask the M3 owner to
   export a public exception and switch `skip_job` to it.
5. **`classify_exit` of `syft-grype` may raise `ToolPreparationError`** (it reads the tail of the job log) so that the stale-database reason replaces the
   generic "exit code 1" text; the executor catches it as for any preparation error. A `explain_failure(ctx, exit_code, logs)` hook in the executor would be cleaner.
6. **Failed tools block, they are not skipped**: Dependency-Check without NVD data and Grype without a database end the job `failed` with the instruction
   to start the update. The worker queues the first update of every empty feed at start-up (`SECURESCAN_CONTENT_BOOTSTRAP`), but Dependency-Check needs an NVD
   key (or a mirror) first.
7. **`run_regression(kind)` is `async`** (it runs containers) and takes an optional candidate directory. `run_regression_detailed` returns the outcome object. Minimal
   gate: Semgrep candidate rules must run on the planted apps without rule errors, and every `verified: true` expectation must still be found (raw report read
   only for this gate); with no verified expectation at all the candidate must still produce one finding. Nuclei: at least 200 templates and `nuclei -validate`.
   The first installation of a feed skips the Semgrep gate (nothing to regress against); the gate fails closed when the sample apps are not mounted.
8. **A semgrep-rules directory is `rules-<full commit>`** (not shortened), a rejected candidate is kept as `rules-<commit>.rejected`, previous versions are
   pruned beyond `SECURESCAN_CONTENT_KEEP_VERSIONS` (3). Feed age of rules and templates counts from the last successful *check* (`fetched_at`), of the two
   databases from the upstream build date (`built_at`).
9. **SonarQube server password**: the database password is in the container environment (`SONAR_JDBC_PASSWORD`), as in the plan; the CA certificate is copied
   to `<data root>/sonarqube/db-ca.crt` and bind-mounted. The server's tmpfs mounts get the `exec` option (Elasticsearch native libraries); the scanner's `/tmp` too
   (S3 tries noexec first). Both are stricter-than-needed relaxations that S3 should settle.
10. **`syft-grype` is the job name** (as the plan and design profile say) while `reports/snapshot.py` knows `syft` and `grype` (`TOOL_LABELS`, `COMPONENT_TOOLS`).
    See open issue 3.

## Not verified, and how to verify on Ubuntu 24

Run first, from `backend/`: `uv run ruff format . && uv run ruff check . --fix && uv run mypy securescan && uv run pytest tests/unit -k m8`, then the whole unit suite.
- **Lint and types**: expect E501 on long docstrings and comment lines (add `E501` to the ruff ignores, as the M3 notes suggested) and mypy findings on `Any`.
  `httpx.MockTransport` tests, `FakeSession` interplay and the `_value.get()` read of a Gauge in `test_m8_sonarqube_lifecycle.py` are the likeliest test-side surprises.
- **Image entrypoints** (`entrypoint: null` for syft, grype, dependency-check, spotbugs, skopeo, sonar-scanner, sonarqube-server): the commands are arguments only
  and rely on each image's own entrypoint. `docker image inspect <image> --format '{{.Config.Entrypoint}} {{.Config.Cmd}}'` for each; fix `entrypoint`/`command` in
  `scanners/catalogue.d/*.yaml` if one differs. For `sonarqube-server` the command `/opt/sonarqube/docker/sonar.sh` is a guess from the image layout.
- **Flags** (spike S7 `flags_not_in_help`): `--disableVersionCheck`, `--disableNodeAudit/--disableYarnAudit/--disablePnpmAudit`, `--nvdDatafeed`, `-maxHeap`,
  `-xml:withMessages=<file>`, `grype -o json=<file>`, `syft -o syft-json=<file>`, the `nvd.api.key` property name, Dependency-Check exit code 14, whether a read-only
  data mount works (`SECURESCAN_GRYPE_DB_READ_ONLY`, `SECURESCAN_ODC_DATA_READ_ONLY`, both default false).
- **SonarQube (S3)**: start on a read-only root filesystem with exec tmpfs (`SECURESCAN_SONARQUBE_READ_ONLY_ROOTFS=false` is the switch), the setting name
  `sonar.multi-quality-mode.enabled` for Standard Experience (a failure is logged and reported, not fatal), `additionalFields=rules` in the issues export (set the
  client argument to None if DefectDojo's parser objects), the `SonarQube Scan` import of the zip, whether hotspots must be exported too (not done), `-Dsonar.java.binaries`
  without classes (`SECURESCAN_SONARQUBE_EMPTY_BINARIES_FALLBACK=true` if the pinned build refuses), `vm.max_map_count`.
- **Socket proxy (S2)**: named volumes as `Binds` (`securescan_sonarqube_data:/opt/sonarqube/data`), `ulimits`, `StopTimeout`, two networks in `NetworkingConfig`, the
  container names `securescan-updater-*`, `securescan-regression-*` and `securescan-job-<id>-syft|skopeo`; the regexes in `deploy/socket-proxy/args.env` already cover the names.
- **Content updaters**: run `python scripts/dev.py` up, wait for the bootstrap (`GET /api/v1/scanner-health` shows a version per feed), then `PUT /api/v1/content/nvd-key`
  and `POST /api/v1/content-versions/updates {"feed": "nvd_data"}` (20+ minutes). Pin `commit` in `content/semgrep-rules.lock` from the version shown (never guess it).
  Check `ls -l /var/lib/docker/volumes/securescan_content/_data/semgrep` (link `rules` to `rules-<commit>`), an injected invalid rule is rejected
  (`rules-<commit>.rejected` kept, `securescan_content_update_failed{feed="semgrep_rules"} 1` on the worker's port 9100).
- **Acceptance of the plan**: `SECURESCAN_INTEGRATION=1 python scripts/dev.py test integration -k scanners_all` (six tools on `java-planted` after `sh scripts/build_planted_jar.sh`;
  optional scenarios and their variables are listed in the module docstring); `docker ps` during and 15 minutes after a SonarQube job; Grype with
  `SECURESCAN_GRYPE_DB_MAX_AGE=1h`; `docker inspect` of a scan container shows no NVD key or token except `SONAR_TOKEN` of the SonarQube scanner.
- **Gaps not exercised**: the `egress_lease`/`ensure_egress` squid recreation while a Dependency-Check scan holds a lease (a changed allowlist drops connections), a
  SonarQube job during the idle stop, worker crash during the Syft stage (the Syft container is named `securescan-job-<id>-syft`, which `recover_jobs` does not look for, so an
  orphan finishes by itself and is removed by the launcher).

## Open issues for other milestones and files

1. **M7/M9/M11, egress isolation**: the shared proxy is on `backend`+`egress`, so its clients (skopeo, updaters, Dependency-Check) sit on the routable `backend` network and could
   bypass it. Add the proxy to an internal network all clients can use (for example `dast`, or a new `egress-clients` network created in Compose) and set
   `SECURESCAN_EGRESS_CLIENT_NETWORK` to it. The squid configuration also allows only ports 80 and 443 (a registry on port 5000 needs `SECURESCAN_IMAGE_REGISTRY_DIRECT_HOSTS`).
2. **`deploy/compose.yaml` (worker service; not editable here)**:
   - `SECURESCAN_IMAGE_SYFT`, `_GRYPE`, `_DEPENDENCY_CHECK`, `_SPOTBUGS_FSB`, `_SONARQUBE`, `_SONAR_SCANNER`, `_SKOPEO`, `_NUCLEI` (each `${IMG_<NAME>:?run pin-images first}`);
   - secrets `sonarqube_db_password` (already defined) and `sonarqube_admin_password` (to define: `file: ./secrets/sonarqube_admin_password`, created by `dev.py secrets init`) for
     the worker, with `SECURESCAN_SONARQUBE_DB_PASSWORD_FILE` and `SECURESCAN_SONARQUBE_ADMIN_PASSWORD_FILE`; optionally `SECURESCAN_NVD_API_KEY_FILE`;
   - read-only mounts `../content/semgrep-rules.lock:/app/content/semgrep-rules.lock` and `../backend/tests/fixtures/sample-apps:/app/backend/tests/fixtures/sample-apps`
     (the regression gate fails closed without the apps; or set `SECURESCAN_REGRESSION_APPS_DIR`);
   - the `grype_db` and `odc_data` volumes can go (deviation 1);
   - the API container needs the catalogue (`COPY scanners /app/scanners` in `deploy/backend/Dockerfile`, M3 issue) for digests on the health page; without it the page falls back to job data.
3. **M5 (`reports/snapshot.py`)**: add `"syft-grype"` to `COMPONENT_TOOLS` and `TOOL_LABELS`, and have the components section also accept SBOM artifacts of the job
   (it already reads `ArtifactKind.SBOM` scan-wide, so counts work). Findings of tool `syft-grype` and `dependency-check` count under A06 only once the name matches.
4. **M3 (`executor.py`)**: a public skip exception and an `explain_failure` hook (deviations 4 and 5); `JobOut` in `api/scans.py` does not expose `options`, which the
   integration test reads from the database (the web portal needs the quality gate: expose `options["quality_gate"]` and `measures` or add a results endpoint).
5. **M11**: `refresh_db_gauges` does not know the feed gauges of the API process (they are set when `/scanner-health` is read and, in the worker, at start-up and after each
   update); scrape the worker's port for `securescan_feed_age_seconds`, `securescan_feed_stale`, `securescan_content_update_failed`. `run_regression` is the hook M11 extends
   (monthly image bumps, the Juice Shop run for Nuclei); alert rules for the three metrics. Add `E501` to the ruff ignores.
6. **M6 (portal)**: Settings pages for scanner health and content use `GET /scanner-health`, `GET /content-versions`, `POST /content-versions/updates`, `GET`/`PUT /content/nvd-key`.
7. **M2/M4**: a registry credential reaches the image source through `Target.credential_id` (kind `registry`, secret `user:password` or JSON with `username` and `password`);
   no endpoint creates such a credential yet (the vendor-token endpoint of M7 does not accept kind `registry`).
8. **Executor transaction**: `prepare` runs in one open database transaction, and `ensure_running` can take ten minutes inside it (SonarQube start). Harmless without
   `idle_in_transaction_session_timeout`; if M11 sets one, give `prepare` a short transaction.
9. **Semgrep rules bundle**: the lock's default filter drops rule files with no licence stated only when `missing_license: drop`; the default allows them under the
   repository's own licence. Have the legal reviewer confirm before the first production update.
