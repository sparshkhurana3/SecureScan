# M5 build notes: reports and templates

Written on a machine with no Docker, uv, Python 3.14, Node 24 or installed dependencies, so **nothing was executed**. The only check
run was `python scripts/check_imports.py` (byte-compile on Python 3.9 plus import and name cross-check): 0 problems, plus two
throw-away checks with plain Python and PyYAML (the two mapping files load, every CWE is in at most one OWASP category, the category
sizes are 34/29/33/40/20/3/22/10/4/1 = 196, and the regular expressions of the template check accept the default template and reject
the hostile samples). Jinja2, pydantic, pypdf and WeasyPrint were not available here, so the template, the renderer and the PDF code
have never run.

## What was built

Mappings and snapshot
- `backend/securescan/reports/mappings/owasp-top10-2021.yaml`: all ten OWASP Top 10:2021 categories with their official CWE lists
  (196 CWEs), header comment with source URL and version.
- `backend/securescan/reports/mappings/cwe-top25-2024.yaml`: the 2024 CWE Top 25 (rank, CWE, name), header with source URL.
- `backend/securescan/domain/mappings.py`: loaders (highest `<name>-<year>.yaml` wins), `owasp_category_for_cwe`, `top25_entry_for_cwe`,
  `owasp_categories`, `top25_entries`, `mapping_versions`, `parse_cwe`; rejects a file that lists a CWE twice.
- `backend/securescan/reports/snapshot.py`: pydantic `Snapshot` (header, vendor, summary with counts by severity / tool / OWASP category /
  CWE Top 25 and delta, findings, triaged findings, code quality, components, coverage, methodology, the five known limits, review),
  `build_snapshot` (duck-typed input, no database), `previous_from_snapshot`, `with_review`, `canonical_json`, `snapshot_sha256`,
  `load_snapshot`.
- `backend/securescan/reports/sample.py`: a complete sample snapshot (application and vendor kind) with a `<script>` title, used by the
  template test render, the preview endpoint and the tests.

Rendering and templates
- `backend/securescan/reports/renderer.py`: `SandboxedEnvironment(autoescape=True)` that loads only from the template directory,
  `render_html` (CSS inlined, `<img>` and CSS `url()` turned into `data:` URIs, stylesheet links inlined), `render_pdf` (WeasyPrint with a
  URL policy that allows `data:` and files below the template directory only, class-based `URLFetcher` of WeasyPrint 68+ with a function
  fallback), `render_report`, `static_problems`, `check_template` (static checks plus test render of the application and vendor sample,
  plus a PDF render when WeasyPrint is installed), `check_template_isolated` (the same in a child process with a wall-clock timeout, a
  60 s CPU limit and a minimal environment: `python -m securescan.reports.renderer --check DIR template.html`).
- `backend/securescan/reports/template_package.py`: safe zip reading (allowed extensions only, 20 MB zip, 20 MB per file, 60 MB unpacked,
  200 files, no links, no encrypted entries, no odd or escaping names, no duplicates by case; a single top-level folder is flattened),
  `zip_directory` (reproducible), `write_files`, digests.
- `backend/securescan/reports/watermark.py`: `stamp_pdf` (pypdf only: a Helvetica content stream merged into every page), `stamp_text`,
  `pdf_text`.
- `backend/securescan/reports/templates/default-sonacomstar/{template.html,style.css,brand/wordmark.svg}`: cover with wordmark and verdict
  box, executive summary or summary, top risks, delta, per-tool counts, per-category table and inline-SVG bar chart, CWE Top 25
  presence, detailed findings, triaged findings, conditions, code quality, components, coverage, tool versions, methodology, known limits,
  review block. Black and white, A4, `@page` numbering ("Page n of m"), severity by label and weight. The wordmark is the same file as
  `frontend/src/brand/wordmark.svg`.

## Deviations from the plan or the design, and why

1. **`cwe-top25-2024.yaml`, not `cwe-top25-2025.yaml`.** The 2024 list is the edition I could reproduce completely and verify; the file
   name states the year of its content, as the task asked. To move to a newer edition add `cwe-top25-<year>.yaml` with the same layout;
   the loader takes the highest year and each report records the versions it used. Please record this in `docs/decisions.md`.
2. **Descriptions and remediation text are read from DefectDojo when the report is generated**, not from `FindingHistory` (the table has
   no such columns). `fetch_finding_texts` asks DefectDojo for the open findings (at most 2000), and a failure only means the long texts
   are missing. Text of secret findings (Gitleaks) is never shown: only file, line, rule and title.
3. **Counts, verdict inputs and the detailed list use open findings only** (`state_now == "open"`). Findings triaged away are listed in a
   separate "Triaged out" table (at most 500) and counted in `summary.triaged_out`. The report job calls `refresh_scan_state` first, so a
   regenerated report drops findings triaged since; if DefectDojo is unreachable the report uses the last known state and says so in
   the coverage notes.
4. **Dependency-scanner findings (Grype, Dependency-Check) count under OWASP A06** whatever CWE the CVE carries (the CWE still counts for
   the Top 25). A finding without a CWE goes to "No CWE recorded", an unmapped CWE to "Other CWE, not in the Top 10 mapping".
5. **Automatic report kind**: `vendor` when the application type is vendor, else `application`. `POST /reports` can override `kind`.
6. **A review re-renders the same report row**: `apply_review` records the decision, then new snapshot, HTML and PDF artifacts are stored
   next to the old ones and the row points to them (nothing is deleted); `snapshot_sha256` (the report hash) changes. If the render fails
   the review is still saved and `error` says so. A reviewed verdict also updates `Application.last_verdict` when the report belongs to
   the application's last scan.
7. **Review rules** (not in the plan): `confirm` needs a proposed verdict; `override` needs a different verdict and a reason of at least
   5 characters; conditions must name open findings of the report, have a date today or later, no duplicates, and are refused with a
   passing verdict.
8. **No seeder for the built-in template.** The `report_templates` row is created lazily by `ensure_builtin_template` (called by the
   report job, `GET /templates` and `POST /reports`) under an advisory lock, because `db/seeds/` is not in this milestone's file list.
   Every version of the shipped template is copied to `templates/<id>/files` on the artifacts volume; when the shipped files change, a
   new version row is created and inherits the "default" flags. A seeder that calls `ensure_builtin_template(session)` can be added later.
9. **The template test render runs in a child process** (`check_template_isolated`) with a timeout and a CPU limit, not in the API
   process, so a hostile template cannot hang or crash the API. Sandbox violations print as `SecurityError` through a custom `Undefined`
   (`ReportUndefined`), because Jinja's plain classes print an unsafe attribute as an empty string.
10. **The portal HTML cannot use custom fonts** (the plan's CSP has no `font-src`); the PDF can (fonts inside the template are inlined as
    `data:` URIs for WeasyPrint). The default template uses Liberation Sans from the image.
11. **Watermark uses Helvetica and WinAnsi**: characters outside Latin-1 in a user name show as `?`. The stamp is in every page's bottom
    margin at 7.5 pt grey.
12. **CSV starts with a UTF-8 BOM** so Excel reads it correctly; cells go through `csv_safe_row` (`'` prefix for `=`, `+`, `-`, `@`, tab,
    carriage return).
13. Extra endpoints beyond the plan: `GET /reports`, `GET /reports/{id}/snapshot`, `GET /templates/{id}`, `GET /templates/{id}/download`,
    `PATCH /templates/{id}`. Extra audit actions: `report.request`, `report.generate`, `report.view`, `report.download`, `report.review`,
    `export.report_csv`, `template.upload`, `template.upload_rejected`, `template.download`, `template.preview`, `template.set_default`,
    `template.update`.
14. Delta identity of a finding is DefectDojo's `hash_code` (else a digest of tool, CWE, title, file, component, CVE). If a scanner's
    hash includes the line number, a moved finding appears as one fixed and one new.

## Not verified, and how to verify on Ubuntu 24

From `backend/`: `uv run pytest tests/unit/test_reports_*.py -q`, then `uv run ruff format . && uv run ruff check . --fix && uv run mypy securescan`.

Most likely first failures, in order of my own doubt:
- **Golden outline** (`test_reports_render.py`): the expected text was derived by hand from the template and the sample data. A mismatch
  is most likely whitespace or punctuation in the text normaliser or a wrong number; run the test, print `render_text(...)`, compare, and
  fix the outline (the template is the source of truth for wording).
- **Jinja details** in `template.html` (syntax was only checked for balanced tags): `is not none`, `for ... if` filters, `.items()` under
  the sandbox, `loop.index0`. Render once by hand:
  `uv run python -c "from securescan.reports import renderer; from securescan.reports.sample import sample_snapshot; open('/tmp/r.html','w').write(renderer.render_html(renderer.DEFAULT_TEMPLATE_DIR,'template.html',sample_snapshot('vendor'),'0'*64))"`
  and the PDF with `renderer.render_pdf(html, renderer.DEFAULT_TEMPLATE_DIR)`. Open both and look at them: cover, verdict box, chart,
  page numbers ("Page n of m"), black-and-white severity labels, page breaks. The `@page` margin boxes with `string(runref)` and the
  named `cover` page are the CSS most likely to need a tweak.
- **WeasyPrint 70 fetcher**: `build_fetcher` follows the spike S5 pattern (subclass of `weasyprint.urls.URLFetcher` with
  `fetch(url, headers=None)`, `allowed_protocols=("data", "file")`). If the constructor or `fetch` signature differs, fix `build_fetcher`
  only. Check the spike's finding on blocked resources.
- **pypdf stamp**: `PageObject.create_blank_page(None, w, h)` with a direct `DecodedStreamObject` as `/Contents` and `merge_page`. If
  `merge_page` rejects a direct stream, make the overlay with `PdfWriter().add_blank_page` and an indirect stream.
- **Child-process check**: `python -m securescan.reports.renderer --check DIR template.html` must print one JSON line; in the api image
  `sys.executable` is the venv Python. If the container is `read_only`, fontconfig needs a writable cache directory (S5 finding).
- **FastAPI**: `Annotated[UploadFile, File()]` together with `Annotated[str, Form(...)]` in `POST /templates`; the route order of
  `/templates/default/download` before `/templates/{id}/download`.
- **PostgreSQL**: `pg_advisory_xact_lock` call in `ensure_builtin_template`, the join queries in `previous_report_data`, enum comparisons
  (`Scan.state.not_in(...)`).
- **mypy strict**: expect noise in `renderer.py` (`ReportUndefined._undefined_exception`, `URLFetcher` subclass), `snapshot.py`
  (`Any`-typed duck input) and the API response models.

Acceptance run (needs M3, M4 and DefectDojo): scan the planted Java app; within a minute `GET /api/v1/reports?scan_id=...` shows a
ready report; open `/api/v1/reports/{id}/html` in the portal frame or a browser (check the response headers), download `/pdf` and
`pdftotext` it ("Downloaded by", the wordmark text and the verdict on page 1); upload a template zip containing
`{{ cycler.__init__.__globals__ }}` (expect 422, `template.invalid`) and a benign one (201, then preview, then set as default); review a
report with two conditions and read the `report.review` audit event and the regenerated PDF's "Conditions" section.

## Open issues for other milestones

- **`deploy/compose.yaml`: the `api` service has no `artifacts` volume** (only `worker` mounts `artifacts` and `securescan_data`). The API
  reads report files and writes template files and re-rendered reports under `SECURESCAN_ARTIFACTS_ROOT`, and the M2 upload endpoints
  write there too, so the api needs `- artifacts:/var/lib/securescan/artifacts` (read-write) and the `ARTIFACTS_ROOT` default. Without
  it, report downloads fail with `report.file_missing` and uploads never reach the worker. (Owner: M0/M2 deploy files; the fix is one
  `volumes:` entry on `api`.)
- **M4**: `import_job.enqueue_report` matches this milestone's task name and uses `queueing_lock=report:<scan_id>`; the report job also
  guards against a duplicate run (a ready system report younger than 5 minutes is reused). `Scan.verdict` must be final before the
  enqueue (it is read from the scan row). `ScanJob.options` should carry `component_count` for Syft; `FindingHistory` rows are read with
  `scan_findings(..., include_inactive=True)` and `refresh_scan_state` as agreed.
- **M8**: SonarQube job `options` must hold `quality_gate` (`"OK"`/`"ERROR"` or `{"status", "conditions": [{"metric", "status",
  "actual", "threshold"}]}`) and `measures` (`{metric: value}` or `[{"metric", "value"}]`); SBOM files must be `Artifact(kind=sbom,
  scan_id=...)` rows. Both sections render "not available" otherwise.
- **M6**: show `/reports/{id}/html` in an iframe with `sandbox` (no `allow-scripts`); poll `GET /reports/{id}` while `status` is
  `pending`; copy `reports/templates/default-sonacomstar/brand/wordmark.svg` to `frontend/src/brand/` at build if the two should stay one
  file (they are identical now). The review body is `{"decision": "confirm"|"override", "verdict", "reason", "conditions":
  [{"finding_hash", "deadline"}], "internal_notes", "vendor_copy"}`; `finding_hash` is `findings[].key` of the snapshot
  (`GET /reports/{id}/snapshot`).
- **M10**: the vendor flow can use `POST /reports` with `kind=vendor` and `vendor_copy`, and the review endpoint; the vendor copy hides
  internal notes in the rendered report.
- **M11**: add `report.*`, `template.*` audit actions to the audit documentation; the template check needs a writable temp directory
  and CPU in the api container; consider a seeder calling `ensure_builtin_template`.
- **docs/backend-conventions.md** (M2 owns it): add the two job names, `reports/` layout and the endpoint list above if the next
  agents need them.
