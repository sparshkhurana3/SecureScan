run; every findings file in `docs/spikes/` is a template with empty cells. The writing machine had no Docker, no `uv`, no network services and no credentials.
Python files were byte-compiled with Python 3.9 and checked for undefined names; shell scripts with `sh -n`.

## What the user must run, in this order

1. Finish M0 on Ubuntu (`uv lock`, `sh scripts/build_planted_jar.sh`, `dev.py secrets init/certs/pin-images`). S5 needs `backend/uv.lock`; S7 needs the planted jar.
2. **Start now, 20+ minutes in the background:** `NVD_API_KEY=<key> sh spikes/s7/odc_update.sh`.
3. `sh spikes/s7/prefetch.sh all`.
4. Fill the two SpotBugs checksums (`scanners/spotbugs/README.md`, observed values are listed there for cross-checking), then
   `SPOTBUGS_SHA256=... FSB_SHA256=... sh spikes/s7/build_spotbugs.sh`.
5. `sh spikes/s7/run_all.sh` (S7). Fill `docs/spikes/s7-scanner-contract.md`; set `verified: true` in the `expected-findings.yaml` entries that were confirmed.
6. `sh spikes/s2/run.sh all` (S2). Paste the allowlist into `deploy/socket-proxy/args.env` in M3.
7. `sudo sysctl -w vm.max_map_count=524288`, then `uv run --project backend python spikes/s3/run.py` (S3; writes `sonarqube-issues.zip`).
8. Start the S1 stack (commands in `docs/spikes/s1-defectdojo.md`), then `DD_ADMIN_PASSWORD=... uv run --project backend python spikes/s1/run.py` (S1).
9. `sh spikes/s5-weasyprint/run.sh` (S5); commit `docs/spikes/weasyprint-sample.pdf`.
10. S4 and S6 when the Entra test tenant (or mock) and the GitHub App exist (env variables are documented at the top of each script and in the findings files).
11. `uv run --project backend python spikes/s8/run.py` (S8).
12. Fill every findings file, record deviations in `docs/decisions.md`, tick M1 in `docs/progress.md`.

## Deviations from the plan or the design (with reason)

1. **Findings file and directory names** follow the task (`s1-defectdojo.md` ... `s8-opengrep.md`) instead of the plan's `defectdojo.md`, `scanner-contract.md`, `sonarqube.md`, `entra.md`, `github.md`, `opengrep.md`. The mapping is in `docs/spikes/README.md`. Directories are `spikes/s1`, `s2`, `s3`, `s4`, `s6`, `s7`, `s8` (the paths the plan names) and `spikes/s5-weasyprint` (the path the task names).
2. **`system_settings` is superuser-only in DefectDojo 3.4.0** (source of `dojo/system_settings/api/views.py`: `IsSuperUser`). The design's `dojo-init` (step 3 to 4: "creates the `securescan-sync` staff user ... turns deduplication on") cannot do the second part with the staff token. S1 probes both tokens. Likely outcome for M4: `dojo-init` uses the `securescan-accounts` superuser token (or the admin account) for system settings. Not decided here.
3. **`email` is required** when creating DefectDojo users (`UserSerializer`), and **a password cannot be set by PATCH** ("Update of password though API is not allowed"). Consequence for M4: the portal generates the initial password at creation; a lost password means delete and recreate (or the DefectDojo UI reset).
4. **`force_password_reset` is on `/api/v2/user_contact_infos/` (superuser), not on `/users/`, and `api-token-auth` refuses users who owe a reset.** Fine for people, wrong for service accounts. S1 step 9 verifies.
5. **Findings API batch filter:** the source defines `id = NumberInFilter(...)`, so `?id=1,2,3` is the likely working form, not `id__in`. S1 probes both.
6. **S7 discovers writable paths with `docker diff`** from a run without `--read-only`, then verifies with the hardened run; the plan only said "record which paths must be writable".
7. **S6 extends the plan's clone step.** `git remote remove origin` deletes `refs/remotes/origin/*`, so after `git clone --no-single-branch` every branch except the checked-out one would vanish and Gitleaks (`git log --all`) would scan less than the full history. The spike copies remote-tracking branches to local branches first and asserts the commit count is unchanged. M3's `sources/github.py` must do the same.
8. **S7 does not run SonarQube**; the scanner facts for it come from S3.
9. **S5 renders twice** (plain and hardened) to learn which paths WeasyPrint needs writable (fontconfig cache).

## Could not verify (and how to verify on Ubuntu)

Everything. Specifically the likeliest points of failure:

- **S1 compose:** copied from the 3.4.0 tag; the only edits are removing `build:`, defaults, `DD_ADMIN_PASSWORD`, loopback ports. If the initializer fails, read its log.
- **S2:** `wollomatic/socket-proxy` runs `FROM scratch`; the compose gives it `user: 65534:<docker gid>`. Whether the proxy matches the query string, cleans `..` before the bind check, or accepts `-allowfrom=client` with a compose service name is exactly what the run decides. The regexes the script derives are strict (64-hex id or the name `sonarqube`).
- **S3:** the Mode setting key `sonar.multi-quality-mode.enabled` is real (checked in SonarQube's source) but is a hidden property; `POST /api/settings/set` may refuse it. Whether the service user can create a `PROJECT_ANALYSIS_TOKEN` with only the `provisioning` and `scan` permissions is open (the script says so if not). The network name `securescan-spike-s3_s3_sonarqube` assumes the compose project name in the file.
- **S4:** Authlib's `OAuth2Client(code_challenge_method=..., token_endpoint_auth_method=...)` and `fetch_token(grant_type=..., code=..., code_verifier=...)` were written from memory of Authlib 1.x.
- **S5:** the WeasyPrint 70 `URLFetcher` subclass API (documented for current versions) with a fallback for the function API; the exact exception behaviour for blocked URLs.
- **S7:** every flag in the plan's command lines is unverified against the pinned images; `check_flags` prints which are not in `--help`, and Dependency-Check optional switches are dropped when not listed. SpotBugs `-xml:withMessages=FILE` versus `-output` is tried both ways. `-silent` for ZAP and the report job's `reportFile` behaviour are unverified.
- **S8, S6:** GitHub API fields (`assets[].digest`, `/installation/token` DELETE) are standard but not exercised.
- `python scripts/check_imports.py`: see below.

## Open issues for other milestones

- **M0 / sample apps:** `js-planted` has `package.json` but **no `package-lock.json`** (the plan, M0 task 12, asks for one); Syft and Dependency-Check will likely find nothing for it, so `grype` and `dependency-check` expectations for js-planted are empty. `java-planted`'s `log4j-core` is declared in `pom.xml` but is not inside the committed jar, so Dependency-Check probably finds nothing there either; only Syft/Grype read the pom. Consider a shaded jar or a lock file so every dependency scanner has a certain target. Not changed (files not owned by M1).
- **M0 / `deploy/compose.yaml`:** the `socket-proxy` service has no `user:`; the image is `FROM scratch` and, per its README, needs a numeric user in the Docker socket's group (`user: "65534:<gid>"`). `deploy/socket-proxy/args.env` uses `SP_ALLOW_*` variable names, which match the README of 1.13.1 (checked); numbered variants (`SP_ALLOW_GET_2`) are how several patterns are given. M3 must also set `SP_LISTENIP=0.0.0.0` (already there) and `SP_ALLOWBINDMOUNTFROM`.
- **M3:** `runner/sources/github.py` must keep all branches before removing the remote (deviation 7). Root images with `--cap-drop ALL` lose DAC override: workspace files must be world-readable (S7 checks Gitleaks as root).
- **M4:** items 2 to 4 above.
- **M8:** Semgrep rules copied by S7 are not licence-filtered (the updater must filter by `metadata.license`); the SonarQube issues export does not include hotspots (S3 records whether the parser needs them); SpotBugs heap default 768 MB.
- **M9:** S2's deny test must be re-run after the DAST network work (`spikes/s2/run.sh enforce`).
- **Docs:** `docs/spikes/README.md` lists the renamed findings files; the plan's references to the old names are not edited.
